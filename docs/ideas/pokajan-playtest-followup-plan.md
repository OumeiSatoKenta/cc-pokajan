# ポカジャン Step 10 — プレイテスト反映（待ち表示・ゲーム風UI・横向き再設計）計画書

## 背景（Context）

Step 9（カジノ風リニューアル）完了後のプレイテストで出た指摘と、9-3 の申し送りに対応する。

- **待ち表示のちらつき**: 待ち一覧が手札の**上**（`.table__mine` 内で header→待ち→河→手札）にあり、
  テンパイの成立/崩れで待ちパネルが出入りするたび手札の位置がずれる。
- **UI がゲームっぽくない**: 操作ボタンが全部同じ金ピル。ツモ/ロン/見送るの区別や押下感が薄い。
- **横向きの縦 fit 未達（9-3 保留）**: portrait 用 DOM を CSS で畳むだけでは 390px に収まらなかった
  （実測 約540px）。横向き専用の再設計が要る。

### 確定方針（ユーザー確認済み）

- 待ち表示: **「待ち」をホバー/タップで展開**（常時はコンパクトなトリガのみ。フロー外オーバーレイ）
- ゲーム風UI: **対局中の操作エリア＋全画面のボタン共通**（`.button` ベースも手を入れる）
- 横向き再設計: **今回のプランに含める**

### 依存関係

**Step 1（待ちのホバー展開）→ Step 3（横向き）** の順が要。待ちをフロー外に出すと、
9-3 で最大の縦あふれ要因だった待ちパネル（テンパイ時 ~80–228px）が消え、横向き fit が現実的になる。
Step 2（ボタン）は独立だが、横向きが最終ボタンを縮めるので Step 3 より前に置く。

### 一次資料

外注デザイン第2稿 `ポカジャン 対局画面 第2稿.dc.html` の
`buildAction()`（ツモ=緑 `#a8e6c2→#5cb185` / ロン=赤 `#ffb3ab→#e0685f` / ゴースト、影付き）と
`SIZE.land`（横向き寸法）。視覚仕様として参照する。

## Step 10-1: 待ちのホバー/タップ展開（ちらつき解消）

**狙い**: 待ち一覧をフローから出し、手札の位置を固定する。常時は「待ち N件」トリガだけ、
ホバー（PC）/タップ（タッチ）でチップ一覧をオーバーレイ表示。

- **配置**: トリガを**常時存在する行**（`.table__mine-head`）に置く。テンパイ時だけ「待ち N件」を出す
  （header 自体は常にあるので手札は動かない）。一覧は `.card-counts` と同じく**絶対配置のオーバーレイ**
  で手札の上に浮かせる（`.hand-area` か `.table__mine` を `position: relative` の基準にする）。
- **開閉**: React state で click/tap トグル（ピン留め）＋ CSS `:hover` で覗き見。両対応で touch でも使える。
  Escape / 外側クリックで閉じる。`aria-expanded` を付ける。
- **振る舞いは不変**: 並び（生存優先→点数降順）・6件＋「他N件」・残0淡色は `WaitPanel` の既存ロジックを
  そのまま使う。表示の器だけ差し替える。
- **既存の参考**: 残枚数ツールチップ（`hints.css .card-counts` ＋ `Hand.tsx` の `.hand-area` 基準の
  hover）と同じ手法。z-index は card-counts と競合しないよう整理。

**対象ファイル**:

- `src/ui/components/WaitPanel.tsx` — トリガ＋オーバーレイの開閉構造に。並び/上限/残0 のロジックは維持
- `src/ui/screens/TableScreen.tsx` — 待ちを header 側トリガへ移し、手札上の常時フロー配置をやめる
- `src/ui/hints.css` — トリガchip・オーバーレイのスタイル（`.wait` 系を流用/改称）
- `tests/ui/waitPanel.test.tsx` — 新構造に追随（**不変条件＝並び・残0・6件上限は引き続き検査**）
- E2E: テンパイに到達させ、トリガ表示→展開で一覧が出る／閉じられることを1件（既存 `playUntil…` を活用）

**受け入れ**: テンパイ成立/崩れで**手札の位置が動かない**。展開で待ちが読め、閉じられる。touch でも開ける。

## Step 10-2: ゲームっぽいUI（操作ボタン＋全画面ボタン共通）

**狙い**: ボタンに色・グラデ・影・押下感を与え、対局の操作を種類で色分けする。全画面に波及。

- **操作ボタンの色分け**: `ActionBar` が `item.kind` で class を出し分ける
  （`declare`→`button--tsumo` 緑 / `claim`→`button--ron` 赤 / `pass`→`button--ghost`）。
  ラベルは既存どおり役名＋点数入り（`actionBarItems`）。
- **ボタンの質感（全画面）**: `App.css` の `.button` ベースにグラデーション・影・`:active` の押下 transform を
  付ける。`.button--primary`（金）はタイトル/BET/精算/設定でも使われるので、そこも一緒にゲーム風になる。
  `@media (prefers-reduced-motion: reduce)` で押下 transform を無効化。
- **操作エリア/タイマー**: 操作エリアに軽い枠（第2稿 `--actionBg`）、タイマー3種（打牌/宣言/割り込み）の
  色分けを仕上げる（`table.css`）。

**対象ファイル**:

- `src/ui/components/ActionBar.tsx` — kind → class の出し分け
- `src/App.css` — `.button` ベースの質感（全画面波及）
- `src/ui/table.css` — `.button--tsumo` / `.button--ron` / `.actions`（枠）/ `.timer` の仕上げ
- 確認: `src/ui/casino.css` / `src/ui/settings.css`（`.button` を使う他画面が破綻しないか）
- テスト: 単体は class の出し分け（renderToStaticMarkup）。見た目は目視

**受け入れ**: ツモ=緑/ロン=赤/見送る=ゴーストで一目で分かる。押下感がある。他画面のボタンも統一され破綻しない。

**注意**: **全画面波及**なので、タイトル/BET/精算/設定の目視が範囲。色のコントラスト（accent 地の文字）は
9-1 の `.wait__same` と同じ轍を踏まないよう、`.button--primary` 等の文字色を検算する。

## Step 10-3: 横向き専用レイアウトの再設計（縦 fit を達成）

**前提**: Step 10-1（待ちがフロー外）完了。これで横向きの最大の縦あふれ要因が消える。

**狙い**: 9-3 で保留した「844×390 に収める」を、CSS の縮小だけでなく **DOM 再構成**で達成する。

- **下段をレール化**: 手札と操作バーを1つのラッパにまとめ、横向きで **[手札 | 操作]** の横並びにする
  （縦では従来どおり縦積み）。現状 `.table__mine`（3×3グリッドの bottom）と `.actions`（felt の外）が
  別コンテナなので、**両者を包む `.table__controls` を TableScreen に導入**し、CSS で向きに応じて
  column/row を切り替える。※ portrait の見た目を壊さないことを E2E 座標で担保。
- **他家席の簡略化（横向きのみ）**: 左右席の伏せ札7枚縦積みが縦を食う主因。横向きでは伏せ札を
  横並び（枚数バッジ or 数枚＋「×7」）に畳む、席の情報密度を下げる。
- **反復検証**: 9-3 で使った E2E の高さ実測（`scrollHeight - clientHeight`）を**目標 ≤ 1（fit）**に戻し、
  実測しながら詰める。到達したら回帰ガードとして残す。**達成できたら「保留」を解除**。
- **既存の landscape.css を土台に**（密度低下・2カラム→レール化・ドット化・チップ横スクロールは流用）。

**対象ファイル**:

- `src/ui/screens/TableScreen.tsx` — `.table__controls` ラッパ導入（DOM 再構成。testid/aria は維持）
- `src/ui/landscape.css` — レール化・他家席簡略化・fit の詰め
- `src/ui/board.css` — 席の簡略化に伴う調整（必要なら）
- `src/ui/components/PlayerSeat.tsx` — 横向きで伏せ札を畳む表示（CSS で足りなければ最小の分岐）
- `tests/e2e/table.spec.ts` — 横向き E2E を **縦 fit（≤1）** に強化。375px 縦・座標検査が維持されること

**受け入れ**: 844×390 で**縦横ともスクロールが出ない**。縦 375px・デスクトップが破綻しない。
達成できなければ到達値で正直に据え置き、理由を記録（9-3 と同じ誠実さ）。

**リスク**: DOM 再構成が portrait のグリッド（3×3・座標 E2E）を壊しうる。座標検査と 375px 検査で担保し、
`.table__controls` は「縦では現状と同じ積み順」になるよう設計する。
