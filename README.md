# ポカジャン（cc-pokajan）

「ホロライブドリームス（ホロドリ）」のカジノミニゲーム **「ポカジャン！」** を再現したウェブゲーム。
1人 + CPU3人での対局と、BET → 対局 → 精算のカジノループをブラウザ上で完結させることを目指す。

> **著作権について**: ゲームルール自体に著作権は及ばないため再現に問題はないが、公式イラスト・ロゴ・
> キャラクター画像はリポジトリに一切含めない。同梱のロスターはオリジナルの創作キャラで構成しており、
> 好みの素材はロスター設定画面からアップロードして差し替えられる。

## ゲーム性

麻雀 / ドンジャラの簡略版。役は2種類しかないが、**和了しても局が終わらない**（カードを補充して連続和了できる）点が独特で、常に打点レースが続く。

- 4人対戦。手札は常に **7枚**、「山から1枚引く → 1枚捨てる」を繰り返す
- 開局時に「今回登場するグループ（4つ）」と「ボーナスメンバー」が発表される
- 山札が尽きる or 誰かの点数が0以下になったら終了

### 役

| 役      | 条件                     | 基本点 | 同色時  |
| ------- | ------------------------ | ------ | ------- |
| 3カード | 同一メンバー3枚          | 120    | 840     |
| 3人組   | 3人グループ全員を1枚ずつ | 180    | 540 (※) |
| 4人組   | 4人グループ全員          | 300    | 840     |
| 5人組   | 5人グループ全員          | 480    | 1800    |

- カードは **ピンク / 青 / オレンジ** の3色。役の構成カードが全て同色だと大幅に加点される
- **ボーナスメンバー**が役に含まれると1枚につき **+90点**
- ツモ相当は他3人が1/3ずつ、ロン相当（他家の捨て札での和了）は捨てた人が全額支払う

(※) 3人組の同色点のみ実機情報が見つからず推定値。`src/config/rules.ts` の `TODO(要実機確認)` を参照。

詳細な調査結果は [docs/ideas/pokajan-plan.md](docs/ideas/pokajan-plan.md) にまとめてある。

`npm run dev` で開く画面で **1局を通して遊べます**。手札をクリックして捨て、
あと1枚で役が完成するカードには黄色枠が付き、他家の捨て札で役が成立すると
宣言ボタンと残り時間バーが出ます。手札にマウスを乗せるとその絵札の**残り枚数**が
色ごとに出ます（自分の手番でなくても調べられます）。

起動時のオプション（URL のクエリパラメータ）:

| パラメータ  | 内容                                                |
| ----------- | --------------------------------------------------- |
| `?seed=N`   | 配牌を固定する。省略時は毎回変わる                  |
| `?fast=1`   | 演出の待ち時間を 0 にする（ルール値には影響しない） |
| `?turnMs=N` | 持ち時間の上限をミリ秒で指定する（E2E 用）          |

### 設計方針

- **エンジン層は React に依存しない**。`src/engine/` と `src/config/` からの `react` import は
  `.oxlintrc.json` の `no-restricted-imports` で禁止しており、`npm run lint` で自動検知される
- **エンジンは `Math.random()` を使わない**。乱数は必ず `Rng` を引数で受け取るため、テストが決定的になり、
  シードから局を完全に再現できる（リプレイ機能の土台）
- **可変数値は `RulesConfig` に集約**。全関数が `rules` を引数で受け取るので、Step 6 のルール設定画面から
  任意の値を注入できる。型は `engine/types.ts`、値は `config/rules.ts` に置き、エンジンが設定層に依存しないようにしている
- **`validateRoster` は信頼できない入力の検証点**。Step 6 でユーザー提供の JSON を読み込むため、
  配列でない・フィールドが欠けているといった壊れた構造でも例外を投げず、エラー一覧として返す
- **点数はカードの選び方に依存しない**。役の点数は「役種・同色可否・構成メンバー」だけで決まるため、
  役判定は「点数を最大化するカードの組み合わせ」を探索する必要がなく、素直な列挙で全候補を洗い出せる
- **正しさを「たまたま成り立っている条件」に依存させない**。同色判定は実際のカードの色から導出し、
  役種として扱えるグループ人数は `types.ts` の定数を役判定とルール検証の双方から参照する。
  Step 6 でルールがユーザー編集可能になっても壊れないようにするため
- **支払いは0クランプと点数保存則を両立させる**。残高不足の相手からは残高分だけを徴収し、和了者は
  実際に徴収できた合計だけを受け取る。これにより「4人の合計点は対局を通じて一定」が常に成り立つ
- **エンジンは時計を持たない**。宣言の受付時間は `TICK(deltaMs)` として UI 層から供給される。
  エンジンが `Date` を触らないため、対局の全経過が「初期シード + アクション列」だけで再現できる
- **CPU に隠し情報を渡さない**。AI は `GameState` ではなく公開情報だけの `AiView` を受け取る。
  他家の手札や山札の中身へ到達する経路が型として存在しないため、カンニングは型エラーになる。
  残り枚数の算出（`unseen.ts`）も同じ形で、`countUnseen` は `GameState` を受け取らない。
  状態に触るのは `toVisibleCards` の1箇所だけに閉じている
- **宣言された役は信じずに再計算する**。`DECLARE` / `CLAIM` が運ぶ候補は検証して通すのではなく、
  エンジンが `findYaku` で計算し直したもので置き換える。点数を偽装した候補を渡しても、
  精算に使われるのは常にエンジンが算出した点数になる

## 実装状況

**Step 1〜8 完了**。計画は
[docs/ideas/pokajan-add-feature-commands.md](docs/ideas/pokajan-add-feature-commands.md) と
[docs/ideas/pokajan-presentation-and-counts-plan.md](docs/ideas/pokajan-presentation-and-counts-plan.md) を参照。

Step 3 の完了により、**ゲームとして成立していることが自動対局で検証済み**です。シードを変えた
CPU 同士の対局100局が例外なく完走し、その全ステップで点数保存則・カード保存則・手札枚数の
不変条件が成立することをテストで固定しています。

Step 4 の完了により、**ブラウザで1局を通して遊べます**。
Step 5 で BET → 対局 → 精算のカジノループが閉じ、
Step 6 で**自分たちの写真とチーム構成に差し替えられる**ようになりました。

Step 7 では**盤面を麻雀ゲームの卓に近づけて**います。
7-2 で上家=左 / 対面=上 / 下家=右 / 自分=下の配置になり、4人全員が伏せ手札と河を持ちます。
7-3 で**座席ごとにプレイヤー画像**を設定できるようになりました（タイトル → プレイヤー設定）。
7-4 で**和了すると進行が止まり**、次へ進まなくなりました（CPU 同士の和了も含む）。
7-5 で**カットイン・得点の増減・順位の移動**が出るようになり、Step 7 は完了しました。

Step 8 はプレイテストで挙がった要望への対応です。
8-1 で和了演出が**カットイン → 点数獲得結果の2段**になり、同色役では大物手バージョンが出ます。
点数獲得結果には**役の構成カード**が並び、確認ボタンは無くなって**数秒で自動的に閉じます**
（クリックで1段進む / Escape でいつでも閉じる）。
8-2 で**残り枚数**が読めるようになりました。手札にマウスを乗せるとそのメンバーの
色ごとの残枚数が出て、テンパイすると**待ち一覧**が手札の上に並びます。
待ちの札がもう場に無い（残0）行は淡く落ちるので、**上がれない待ちを抱えたまま
打ち続けることがなくなります**。
