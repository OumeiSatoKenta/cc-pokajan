# Step 10-1 待ちのホバー/タップ展開 — requirements

## 背景

Step 9 完了後のプレイテストで、**待ち一覧が手札の位置をちらつかせる**問題が出た。
待ちパネルは `.table__mine` 内で header → 待ち → 河 → 手札 の順に**フロー内**に置かれており、
テンパイの成立/崩れで `WaitPanel`（`waits.length === 0` で `null`）が出入りするたびに、
その下の河・手札が上下する。手札は最も見る場所なので、この上下は視認性を大きく損なう。

Step 10-3（横向き fit）の前提でもある。9-3 で最大の縦あふれ要因はテンパイ時の待ちパネル
（最大 ~228px）だった。これをフロー外へ出すことで横向き再設計が現実的になる。

## 確定方針（ユーザー確認済み）

- **「待ち」をホバー/タップで展開**。常時はコンパクトなトリガ（「待ち N件」）のみ。
  一覧は**フロー外オーバーレイ**として浮かせる。

## 要件

### 機能要件

1. **手札の位置がテンパイ前後で動かない。** 待ち一覧はフローを占有しない。
   トリガの出入りでも手札の Y 座標が変わらないこと（デスクトップ幅・座標で検査）。
2. **常時はトリガのみ。** テンパイ時に「待ち N件」トリガを出す。テンパイでないときは何も出さない。
3. **ホバー（PC）で覗き見・クリック/タップで固定（ピン留め）。** touch でも開ける。
4. **閉じる導線**: Escape / 外側クリックで（ピン留めを）閉じる。
5. **`aria-expanded`** をトリガに付け、ピン留め状態を反映する。オーバーレイは `aria-controls` で結ぶ。

### 不変条件（振る舞いは変えない）

`WaitPanel` の既存ロジックをそのまま使う。**器（表示）だけ差し替える。**

- **並び**: 生存優先（残 > 0 が先）→ 点数降順（安定ソート）。
- **6 件上限**＋超過分は「他 N 件」。
- **残0 淡色**: `wait__row--dead`（opacity + line-through）。数は `data-unseen` にも出す。
- 待ちの算出（`computeWaits` の結果）はここで作り直さない。`unseenOf` もそのまま。

### 非機能要件

- **エンジン層（`src/engine/`）は変更しない。** UI 層のみ。
- 残枚数ツールチップ（`.card-counts`）と待ちオーバーレイが重なっても破綻しない（z-index 整理）。
- `prefers-reduced-motion` を尊重（開閉に動きを付ける場合）。

### 付随作業

- **`tmp-design.zip`（プロジェクト直下・作業用）を削除**する。実装と無関係。

## スコープ外

- **ゲーム風ボタン**（Step 10-2）。
- **横向き専用レイアウトの再設計**（Step 10-3）。本 Step では landscape.css は
  「待ちが `.table__mine` のフローから消えたことによる破綻を防ぐ」最小限の追随に留める
  （grid の `wait` セルが空になることへの対応）。fit の詰めは 10-3。

## 受け入れ基準

- テンパイ成立/崩れで手札の Y 座標が動かない（E2E・座標）。
- 「待ち N件」トリガをホバー/タップで一覧が開き、Escape/外側クリックで閉じられる（E2E）。
- 残0 淡色・6 件上限・並びが不変（単体テストで固定）。
- 検証ゲート一式（lint / typecheck / test / build / format:check）＋ `npx playwright test` が PASS。
- `tmp-design.zip` が消えている。
