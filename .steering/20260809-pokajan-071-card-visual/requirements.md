# Step 7-1: カードの表現 — 要求内容

## 背景

盤面を麻雀ゲームに近づける（Step 7）の最初のステップ。
計画は [docs/ideas/pokajan-mahjong-board-plan.md](../../docs/ideas/pokajan-mahjong-board-plan.md)。

本ステップでは**カードの描き方だけ**を用意する。配置の組み替え（4方向レイアウト）は
Step 7-2 で行うため、ここでは既存の配置のまま見た目を差し替える。

現状の問題:

| 対象 | 現状 | 問題 |
| ---- | ---- | ---- |
| 河 | 小さなチップ（角丸の色付きラベル） | カードに見えない。手札との対応が視覚的に取れない |
| 他家の手札 | 「手札 7枚」というテキスト | 卓に牌が並んでいる感じがない |
| ボーナス | 名前のテキスト | 目立たない。麻雀のドラ表示牌にあたる情報なのに埋もれる |

## 要求

### R1: 河をカードの絵で描く

**ユーザーストーリー**
プレイヤーとして、河に何が捨てられたかを手札と同じ見え方で把握したい。

**受け入れ条件**

- [ ] 河のカードが手札と同じ絵（色・名前・画像・グループ記号）で描かれる
- [ ] 河のカードは手札より小さい
- [ ] 枚数が増えても折り返して縦に伸びすぎない
- [ ] 画像を設定したメンバーは河のカードにも画像が出る
- [ ] 河のカードは押せない（捨てる操作と取り違えない）
- [ ] 幅 375px で破綻しない

**優先度**: P0

---

### R2: 伏せ手札を描く

**ユーザーストーリー**
プレイヤーとして、他家が何枚持っているかを牌の絵で把握したい。

**受け入れ条件**

- [ ] 他家の手札が枚数分の裏面カードとして描かれる
- [ ] **裏面に他家の手札の中身が一切出力されない**（メンバー名・画像・記号・色）
- [ ] 枚数は `player.hand.length` と一致する
- [ ] 幅 375px で破綻しない

> **これは情報漏れの要件である。** 他家の手札は `GameState` 上に存在し UI から参照できるため、
> 「描画しないだけ」では実装ミス1つで漏れる。到達経路そのものを断つ必要がある。

**優先度**: P0

---

### R3: ボーナスをカード型で見せる

**ユーザーストーリー**
プレイヤーとして、今局のボーナスメンバーを一目で認識したい。

**受け入れ条件**

- [ ] ボーナスメンバーがカード型のタイルで表示される
- [ ] 画像を設定していれば画像が出る
- [ ] ボーナスであることが分かる印がある
- [ ] ボーナスが複数人でも並べられる（`bonusMemberCount` は可変）
- [ ] 幅 375px で破綻しない

**優先度**: P0

---

## スコープ外

| 項目 | 理由 |
| ---- | ---- |
| 4方向レイアウト | Step 7-2 |
| 他家の河の表示 | Step 7-2（`PlayerSeat` の作り替えと同時にやる） |
| プレイヤーアバター | Step 7-3 |
| 和了演出 | Step 7-4・7-5 |
| カードの質感（麻雀牌風の陰影など） | Step 7-2 完了後に方針を判断する |

## 非機能要件

- **他家の手札が UI に渡らない構造にする**（R2 の「到達経路を断つ」）
- エンジン層は変更しない
- 既存の 612 ユニットテスト / 50 E2E を壊さない
- 検証ゲート: `npm run lint && npm run typecheck && npm test && npm run build && npm run format:check`
