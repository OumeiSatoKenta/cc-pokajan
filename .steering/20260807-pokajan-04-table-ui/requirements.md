# 要求内容

## 概要

ポカジャン再現ウェブゲームの **Step 4（対局UI）** として、エンジンを React に接続する
`useGameLoop` フックと、対局画面一式を実装する。

**このステップの完了をもって、ブラウザで人間が1局を最後まで遊べるようになる。**
Step 1〜3 でゲームロジックの正しさは自動テストで証明済みであり、
本ステップはそれを「触れる」形にすることに集中する。

## 背景

Step 3 までで対局エンジンは完成しているが、以下の理由でまだ遊べない。

- **エンジンは時計を持たない**。宣言の受付時間は UI 層が `TICK` で供給する必要がある
- **エンジンは CPU の思考時間を持たない**。人間が追える速度にするのは UI の責務
- **`reduce` の戻り値は `{ state, events }`** で、React の `useReducer` の契約と直接は噛み合わない
- 現在の `App.tsx` はエンジンの目視確認用プレースホルダで、操作ができない

## 実装対象の機能

### 1. エンジンと React の接続（`src/ui/hooks/useGameLoop.ts`）

- エンジンの `reduce` を駆動し、状態とイベントを React に橋渡しする
- CPU の手番を人間が追える速度で自動進行させる
- 宣言の受付時間を `TICK` で駆動し、時間切れで自動パスさせる
- アンマウント時に全タイマーを解除する

### 2. 対局画面（`src/ui/screens/TableScreen.tsx` + `src/ui/components/*`）

- 自分の手札・他家の状況・場の情報を表示する
- 手札のクリックで捨てる
- リーチ表示（あと1枚で役が完成するカードの黄色枠）
- 割り込み宣言のボタンと残り時間バー
- カードの移動と役成立のアニメーション

### 3. 画面ステートマシン（`src/App.tsx`）

- 画面遷移の骨格を置く。本ステップでは対局画面のみ有効

## 受け入れ条件

### `useGameLoop`

- [ ] `GameState` に手を加えず、UI 層のラッパー状態（`LoopState`）でイベントキューを保持する
- [ ] `createLoopReducer(rules)` が**純粋関数**を返す（副作用をリデューサ内で起こさない）
- [ ] `rules` が変わらない限りリデューサが作り直されない
- [ ] CPU の手番が自動で進行し、各アクションの間に人間が追える間隔が入る
- [ ] 山からの1枚引き（`DRAW`）は人間の手番でも自動で行われる
- [ ] 人間の手番で役が成立していない場合、宣言フェーズを自動で通過する
- [ ] `claimWindow` で人間が未表明のとき、残り時間が減少し、0で自動的にパスされる
- [ ] **人間に割り込める役がない場合、受付時間を待たずに自動でパスされる**（宣言フェーズと対称）
- [ ] **CPU の割り込み判断が、人間の入力を待たずに先に処理される**
- [ ] **受付時間の経過処理が、CPU の割り込み判断のタイマーを妨げない**
- [ ] `selfDeclare` は `declarer` を、`draw` / `discard` は `turn` を対象とする
- [ ] `gameOver` 到達後は自動進行が何も行わない
- [ ] アンマウント時にタイマーが残らない
- [ ] `IllegalActionError` を握りつぶさない
- [ ] `restart()` で前回と異なる配牌の対局が始まる

### 対局画面

- [ ] 自分の手札が並び、**自分の手番の捨てるフェーズでのみ**クリックで捨てられる
- [ ] 他3人の伏せ手札枚数・点数・直近の捨て札が見える
- [ ] 山札の残り枚数・ボーナスメンバー・今局のグループ（達成状況つき）が常に見える
- [ ] **あと1枚で役が完成するカードが黄色枠で強調される**
- [ ] 自分の手番で役が成立しているとき、宣言ボタンが表示される
- [ ] 他家の捨て札で役が成立したとき、宣言ボタンと残り時間バーが表示される
- [ ] 役が成立したとき、役名と点数が一時的に表示される
- [ ] 終局時に順位と最終点数が表示され、もう1局始められる
- [ ] カードの出入りがアニメーションする
- [ ] **`prefers-reduced-motion` が有効な環境ではアニメーションを抑制する**
- [ ] スマートフォン幅（375px）でレイアウトが破綻しない

### 正しさの担保

- [ ] UI がゲームのルールを再実装していない（成立判定は必ずエンジンに委ねる）
- [ ] 人間が操作できるのは、その時点でエンジンが受け付けるアクションだけである
- [ ] 1局を最後まで人間の操作だけで完了できる（E2E で検証）

### 制約の維持

- [ ] `src/engine/` に変更を加えない（UI の都合でエンジンを歪めない）
- [ ] `framer-motion` を対局画面とその配下でのみ import する
- [ ] エンジン層の依存制約に違反しない（`npm run lint` で担保）

## 成功指標

- ブラウザで1局を最後まで遊べる
- `npm test` / `npm run lint` / `npm run typecheck` / `npm run build` / `npm run format:check` が PASS
- Playwright の E2E が PASS（1局を最後まで進めて終局に到達する）
- 本番バンドルが gzip 150KB 以内（PRD の非機能要件）

## スコープ外

以下はこのフェーズでは実装しません:

- タイトル画面・BET 画面・結果画面（Step 5）
- 所持コインと精算（Step 5）
- ロスターエディタ・画像アップロード（Step 6）
- ルール設定画面（Step 6）
- サウンド・BGM（Post-MVP）
- 対局の中断復帰・リプレイ（Post-MVP）
