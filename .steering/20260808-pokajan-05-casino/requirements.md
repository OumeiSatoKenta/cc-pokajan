# Step 5: カジノメタ（BET / 精算 / ウォレット） — 要求内容

## 背景

Step 4・4b で「ブラウザで1局まともに遊べる」状態になった。
現状は対局画面だけが存在し、対局が終わると `ResultOverlay` の「もう1局」で
**無料で**次の対局が始まる。賭ける対象がないため、勝敗に意味がない。

本ステップで **BET → 対局 → 精算** のループを閉じ、プロダクトとして成立させる。

## 要求

### R1: 精算計算

**ユーザーストーリー**
プレイヤーとして、対局の結果に見合った報酬を得るために、
最終点数と順位に応じてコインが増減してほしい。

**確定仕様**（`docs/ideas/pokajan-plan.md` の調査結果より）

```
精算額 = (最終点数 × BET倍率 × 順位倍率) − BET額
```

| 項目       | 値                                              |
| ---------- | ----------------------------------------------- |
| BET 額     | 1000 コイン（1倍）/ 2000 コイン（2倍）          |
| 順位倍率   | 1位 **2.5** / 2位 **1.5** / 3位・4位 **1.0**    |
| 順位の決定 | **エンジンが `GameOver` イベントで確定した順位** |

**受け入れ条件**

- [ ] BET 1000 と 2000 で精算額が倍率どおり（2倍）に変わる
- [ ] 1位・2位・3位・4位で順位倍率が正しく適用される
- [ ] 順位は点数から画面側で導出し直さず、エンジンが確定した値を使う
- [ ] 端数が出る場合の丸め規則が1箇所で定義され、テストされている
- [ ] BET 額・順位が不正な場合は黙って誤った額を返さず、例外になる

**優先度**: P0

---

### R2: 所持コインの永続化

**ユーザーストーリー**
プレイヤーとして、続きから遊ぶために、所持コインがリロード後も保持されてほしい。

**受け入れ条件**

- [ ] 所持コインが localStorage に保存され、リロード後も保持される
- [ ] 初回起動時は初期コインが付与される
- [ ] 保存データが壊れている（不正な JSON・型違い）場合も落ちず、初期値に戻る
- [ ] localStorage が使えない環境（プライベートモード等）でも例外で落ちない
- [ ] 保存形式にバージョンを持ち、将来の形式変更に備える

**優先度**: P0

---

### R3: タイトル・BET・リザルトの各画面

**ユーザーストーリー**
プレイヤーとして、賭け金を選んで対局に臨むために、
タイトル → BET → 対局 → 精算 の流れを画面で辿りたい。

**受け入れ条件**

- [ ] タイトル画面に所持コインが表示され、対局を開始できる
- [ ] BET 画面で 1000 / 2000 を選べる
- [ ] **所持コインが BET 額に満たない場合、その BET を選べない**
- [ ] リザルト画面に4人の最終点数・順位・精算内訳・コインの増減が出る
- [ ] リザルトから「もう1局」（BET 画面へ）と「タイトルへ」を選べる
- [ ] **BET を経由せずに対局を始める経路が存在しない**

**優先度**: P0

---

### R4: 所持コインが尽きた状態からの復帰

**ユーザーストーリー**
プレイヤーとして、負け続けても遊び続けられるようにしたい。

**背景**: R3 のガード（BET 額に満たなければ選べない）だけを実装すると、
所持コインが最低 BET 額を下回った時点で**どのボタンも押せなくなる**。
localStorage に保存されているため、リロードしても回復しない。
**ゲームが永久に遊べなくなる**ため、復帰手段が要る。

**受け入れ条件**

- [ ] 最低 BET 額を下回ったときだけ、コインを補充する導線が現れる
- [ ] 補充後は通常どおり BET を選べる
- [ ] 所持コインが足りている間は補充の導線が出ない（無限に増やせない）

**優先度**: P0（R3 のガードと不可分）

---

## スコープ外

| 項目                             | 理由                                          |
| -------------------------------- | --------------------------------------------- |
| ロスター・ルールの永続化         | Step 6 の範囲。`prefs` の器だけ用意する        |
| キャラ画像（IndexedDB）          | Step 6 の範囲                                  |
| 対局中の中断・復帰               | `GameState` の永続化は v2 以降（計画書 F 節）  |
| 戦績・統計画面                   | v2 以降                                        |
| コイン移動のアニメーション       | 計画書に記載はあるが、Step 5 の必須要件ではない |

## 非機能要件

- **エンジンの純粋性を維持する**: `src/engine/payout.ts` は `src/config/` を import せず、
  `Math.random()` / `Date` を使わない。`rules` は引数で受け取る
- **`src/storage/` はエンジンから参照しない**: 永続化は UI 層からのみ使う
- **精算の値をユーザーが偽造できない**: 精算額は保存せず、
  保存するのは所持コインの残高だけにする（計算は毎回エンジンが行う）
- 検証ゲート: `npm run lint && npm run typecheck && npm test && npm run build && npm run format:check`
- E2E: `tests/e2e/casino.spec.ts`（BET → 対局 → 精算 → ウォレット反映 → リロード後も保持）
