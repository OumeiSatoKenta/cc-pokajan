### 計画と実績の差分

会話でのフィードバックから直接着手したため、当初のタスク分解は存在しない。
実装中に追加で判明したのは3件で、**うち2件は「片側だけ直しても意味がない」形**だった。

| 追加項目                        | 見つかったきっかけ                                     |
| ------------------------------- | ------------------------------------------------------ |
| `.card__image` の CSS 新設      | 切り取り対応のため画像描画を読み直したら CSS が無かった |
| サムネイルを `contain` に変更   | 保存で切らずに表示で切る状態に気づいた                  |
| 名前と記号の重なり解消          | スクリーンショットで発見                                |

### 学んだこと

1. **「切り取らない」は保存と表示の両方を直さないと達成できない。**
   保存時に切るのをやめても、表示が `object-fit: cover` のままなら
   切る場所が移るだけで利用者から見た結果は同じになる。
   **要求は1つでも、実現に必要な変更が1箇所とは限らない。**

2. **Step 6 の検証には穴があった。**
   `.card__image` の CSS が無かったことに Step 6 では気づけなかった。
   ロスター設定のサムネイルは確認したが、**画像を入れた状態で対局画面を開いていない**。
   E2E も同じ範囲しか見ていなかった。
   「新しく作った機能が、既存の画面でどう見えるか」までを検証範囲に含める必要がある。

3. **検証用の画像は、壊れ方が見える形で作る。**
   切り取りの有無は単色画像では判定できない。
   4色の帯を持つ横長（4:1）画像を用意し、**4色すべてが見えていれば切っていない**と
   一目で分かるようにした。テストデータは「通ったか」ではなく
   「壊れていたらどう見えるか」から設計するほうがよい。

4. **文字列の1文字目は `slice` で取ってはいけない。**
   絵文字や結合文字はサロゲートペアなので、`slice(0, 1)` は片側だけを切り出す。
   チーム名に絵文字を使うのは十分ありうる用途で、
   「日本語の名前しか来ない」という前提に正しさを預けていた。

5. **空文字と未設定を区別する。**
   記号の入力欄を空にしたときに `symbol: ''` を保存すると、
   名前を変えても角の表示が追随しなくなる。
   Step 6 の `imageId` でも同じ判断をしており、**同じ形の誤りが繰り返し現れる**。
