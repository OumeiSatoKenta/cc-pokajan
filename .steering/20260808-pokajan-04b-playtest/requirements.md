# Step 4b: プレイテスト反映 — 要求内容

## 背景

Step 4 で対局画面が完成し、ブラウザで1局遊べる状態になった。
自動テスト（334 件のユニットテスト + 9 件の E2E）はすべて通っており、
自動対局100局も完走している。

その状態で**人間が実際に1局遊んだ結果、3件の問題が見つかった**。

いずれも「テストは全部通っているのに、人間には遊べない」種類の欠陥である。
自動対局で検出できないのは次の理由による。

| 検出できない理由                                                                 |
| -------------------------------------------------------------------------------- |
| CPU は `AiView` から `activeGroups` を直接参照できるため、画面表示を必要としない  |
| CPU は思考時間を持たないため、持ち時間の長短に影響されない                        |
| CPU は `hand` を配列として走査するため、並び順に影響されない                      |

**この3点はいずれも「人間だけが必要とする情報経路」であり、
CPU が代理できない領域である。**プレイテストでしか見つからないことが構造的に決まっている。

## 要求

### R1: グループ構成メンバーの可視化

**ユーザーストーリー**
プレイヤーとして、グループ役（3〜5人組）を狙うために、
各グループに誰が属しているかを対局画面で確認したい。

**現状の問題**
`BoardInfo` はグループ名と所持数（`3/4` など）しか表示していない。
どのメンバーが構成員なのかが分からないため、次のいずれもできない。

- 「あと誰を集めればグループが完成するか」を判断する
- 手札のカードが「どのグループの役に効くか」を判断する

グループ役は最大 1800 点（5人組・同色）で、3カード（最大 840 点）より高い。
これが狙えないことは**戦術の半分が機能していない**ことを意味する。

**受け入れ条件**

- [ ] 4つの登場グループそれぞれについて、全構成メンバーの名前が画面に表示される
- [ ] 手札に持っているメンバーと持っていないメンバーが視覚的に区別できる
- [ ] ボーナスメンバーがグループ一覧の中でも識別できる
- [ ] 幅 375px でレイアウトが破綻しない（横スクロールが発生しない）

**優先度**: P0

---

### R2: ロン・打牌の持ち時間

**ユーザーストーリー**
プレイヤーとして、手札を読んで判断するために、
ロンと打牌のそれぞれに十分な持ち時間が欲しい。

**現状の問題**

- 割り込み（ロン）の受付は `claimWindowMs: 4000` = **4秒**。
  8枚の手札と捨て札を照合して役の有無を判断するには短すぎる
- 打牌には**制限時間がまったくない**。
  人間が操作しない限り対局が永久に止まる（放置すると進行が停止する）

**確定仕様**

| 項目           | 仕様                                                                          |
| -------------- | ----------------------------------------------------------------------------- |
| 初期持ち時間   | **20 秒**                                                                     |
| 適用範囲       | **ロン（`claimWindow`）と打牌（`discard`）の両方**。両者で同じ残量を共有する   |
| 短縮の条件     | **使い切って時間切れになったときだけ** 5 秒減る。時間内に打てば減らない        |
| 下限           | **5 秒**（20 → 15 → 10 → 5 で下げ止まる）                                     |
| 打牌の時間切れ | **引いたカードを自動で捨てる（ツモ切り）**                                    |
| ロンの時間切れ | 自動パス（現行動作を維持）                                                    |

「使い切ったときだけ減る」という**非対称性がこの仕様の核心**である。
単純に「毎回減る」にすると、素早く打っているプレイヤーまで持ち時間を失う。

**受け入れ条件**

- [ ] 打牌フェーズでもタイマーが表示され、残り時間が視覚的に分かる
- [ ] 打牌を放置すると、引いたカードが自動で捨てられて進行が続く
- [ ] ロンを放置すると自動パスされ、進行が続く（現行動作の維持）
- [ ] 時間切れを起こすたびに持ち時間が 20 → 15 → 10 → 5 秒と減る
- [ ] 5 秒で下げ止まり、それ以上は減らない
- [ ] 時間内に操作している限り、持ち時間は減らない
- [ ] ロンで使い切った持ち時間が、その後の自分の打牌にも反映される（残量の共有）
- [ ] 持ち時間の3値（初期値・減少幅・下限）が `RulesConfig` にある

**優先度**: P0

---

### R3: 手札の整列

**ユーザーストーリー**
プレイヤーとして、揃いかけの組を目で追うために、
手札が関連するカードごとにまとまって並んでいて欲しい。

**現状の問題**
手札は配牌順・引いた順のまま表示される。
同じメンバーのカードや同じグループのカードが離れた位置に散らばるため、
「あと1枚で3カード」「このグループはあと2人」といった状況を目視で追えない。

**受け入れ条件**

- [ ] 同じグループのカードが隣接して並ぶ
- [ ] 同じメンバーのカードが必ず隣接して並ぶ
- [ ] 引いたばかりの1枚が、他のカードと区別できる位置・見た目で表示される
- [ ] エンジンの `GameState` が保持する手札の順序は変わらない

**優先度**: P1（R1・R2 と違い、これがなくても勝負は成立する）

## スコープ外

| 項目                                   | 理由                                                     |
| -------------------------------------- | -------------------------------------------------------- |
| CPU の持ち時間                         | CPU は即決するため制限時間の概念がない                   |
| 持ち時間の設定画面からの変更           | Step 6（ルール設定画面）の範囲。値は `RulesConfig` に置く |
| 手札の並べ替えをユーザーが選べるようにする | 要求されていない。既定の並びを1つ決める                  |
| カード画像の表示                       | Step 6 の範囲                                            |

## 非機能要件

- **エンジンの純粋性を維持する**: `src/engine/` は時計を持たない。
  持ち時間の計測は UI 層に閉じる
- **既存のタイマー競合対策を壊さない**: Step 4 で作り込んだ
  「自動進行の `useEffect` は決定の同一性だけを依存に取る」構造を維持する。
  ここを崩すと CPU が永久にロンできなくなる回帰が再発する
- **E2E が現実的な時間で回ること**: 持ち時間が 20 秒になるため、
  時間切れを検証するテストが 20 秒待つ構造だと全体のテスト時間が破綻する
- 検証ゲート: `npm run lint && npm run typecheck && npm test && npm run build && npm run format:check`
