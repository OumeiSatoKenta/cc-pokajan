# Step 9-3 横向きレイアウトと待ちチップ — requirements

## 背景

第2稿デザイン反映の3段の最終段。9-1（テーマ）・9-2（河/ヘッダー）完了済み。
全体計画 [docs/ideas/pokajan-casino-table-redesign-plan.md](../../docs/ideas/pokajan-casino-table-redesign-plan.md)。

本ステップは **F 横向きレイアウト** と **G 待ちチップの見た目**、および
**9-2 からの申し送り「board.css の分割」**（433 行、閾値400超）。

## 要求

### 分割（申し送りの履行）
- `board.css`（433行）を分割する。**卓中央の情報集約（`.board*`）を `center.css` に切り出す**。
  board.css は卓枠（rim/felt）・席・河に絞る。挙動・見た目は不変（純粋な移設）。

### G. 待ちチップの見た目（`hints.css` のみ・振る舞い不変）
- 待ち一覧を表形式（grid 行）→ **色ドット＋金枠の丸チップ**に。
- 残0の淡色化・6件上限・生存優先の並びは既実装（`WaitPanel.tsx`）。**CSS だけ**を変える。
- クラス名・testid は変えない（既存テストの契約を壊さない）。

### F. 横向きレイアウト（新規 `landscape.css`・`@media (orientation: landscape) and (max-height: 480px)`）
- 横持ちスマホ（例 844×390）で卓が破綻せず遊べる。**横スクロールを出さない**（硬い要件）。
- 密度を下げる: 余白・フォント・カード・伏せ札を縮小する。
- **【実装後に判明・要件を修正】完全な単一画面 fit（高さ 390px に全部収める）は達成しない。**
  portrait 用の DOM を CSS で縮めるだけでは限界で、実測で 837px → 約540px まで下げたが 390px には
  届かない（待ち一覧・下段・他家席の積み上げが支配的）。**完全 fit は横向き専用の再設計
  （操作バーを手元に取り込む DOM 再構成・他家席の簡略化）が必要**として保留する。
  9-3 では「横スクロール無し＋密度低下＋横向きレイアウト（2カラム/ドット/チップ）が働く」までを達成基準とする。
- 下段（`.table__mine`）を横並びに: **待ち（左）｜手札（右）**の2カラム。操作バーは下の compact なバーのまま。
- グループ進捗を **人数分のドット**に（所持=金）。CSS で `.board__member` をドット化（名前は視覚的に隠す）。
- 待ちは役名列を落として **色ドット・名前・残数・点数の4項目**に（`.wait__yaku` を隠す）。

## 受け入れ基準

- `board.css` が分割され、閾値（400行）を下回る。移設で見た目・挙動が変わらない。
- 待ちが丸チップで表示され、残0が淡く落ちる（振る舞い不変）。
- 横向き 844×390 で**横スクロールが出ず**、横向きレイアウト（下段2カラム・グループのドット化・
  待ちチップ）が働く。縦の完全 fit は保留（上記 F 参照。E2E は縦あふれの回帰ガードのみ）。
- 縦 375px（既存の1列積み）・デスクトップが引き続き破綻しない。
- 自動ゲート（lint/typecheck/test/build/format:check）と E2E が通る。

## 非対象

- 下段を「待ち｜手札｜**操作**」の完全1レール化（操作バーを mine に取り込む DOM 再構成）。
  現 DOM では操作バーは felt の外にあり、1レール化は TableScreen の構造変更を要するため見送る
  （2カラム＝待ち｜手札 ＋ 下の操作バー、で代替）。→ 将来の polish。
- エンジン層（`src/engine/`）の変更。

## 制約

- エンジン非依存。`data-testid`/`aria-label`/`grid-template-areas` の名前を壊さない。
- カード面の色は塗り替えない。
- 横向きの見た目の最終確認は**人の目視が要る**（claude-in-chrome の手動スクショは常時アニメで
  取得困難＝9-1/9-2 と同じ制約。E2E は「横スクロールなし＋描画」で代替）。
