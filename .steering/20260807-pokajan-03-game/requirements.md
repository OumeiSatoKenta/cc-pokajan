# 要求内容

## 概要

ポカジャン再現ウェブゲームの **Step 3（対局状態機械 + CPU AI）** として、対局の進行を司る純粋リデューサ `game.ts`、公開情報だけで思考する CPU AI `ai.ts`、全員 CPU で1局を最後まで回す `autoplay.ts` を実装する。

UI は実装せず、Vitest によるテストのみで検証する。Step 1（型・山札）と Step 2（役判定・点数・支払い）の公開 API だけを前提とする。

**このステップの完了をもって「ゲームとして成立していること」がテストで証明される。** Step 4 以降の UI 作業でゲームロジックを疑う必要がなくなることが本ステップの最大の価値である。

## 背景

ポカジャンの進行は麻雀に似ているが、以下の点で独自の難しさがある。

- **和了しても局が終わらない**。消費したカードを即時補充し、補充で新たな役ができれば連続して宣言できる。「和了 = 局の終わり」という前提のコードは書けない
- **ロンは手番に関係なく割り込む**。捨て札に対して他家3人が同時に宣言しうるため、優先度の解決が必要になる
- **タイマーが絡む**。宣言の受付には制限時間があるが、エンジンに時間を持ち込むとテストが非決定的になる
- **CPU が隠し情報を見られてはいけない**。他家の手札を参照できる位置に AI を置くと、意図せずカンニングする実装になりうる

これらを、時間を持たない純粋関数の集合として設計しきることが本ステップの目的である。

## 実装対象の機能

### 1. 対局状態機械（`src/engine/game.ts`）

- 初期化: ロスターとシードから配牌済みの初期状態を作る
- `reduce(state, action, rules) => { state, events }` の純粋関数として進行する
- 6フェーズ（`draw` / `selfDeclare` / `discard` / `claimWindow` / `resolveClaim` / `gameOver`）の遷移
- 割り込み宣言の優先度解決（強い役優先、同点なら捨て札プレイヤーから近い順）
- 連続宣言（消費 → 即時補充 → 再度宣言チャンス）と暴走ガード
- 終了判定（山切れ / 誰かの点数が0以下）と順位確定
- 演出用 `GameEvent[]` の発行

### 2. CPU AI（`src/engine/ai.ts`）

- 手札から各ターゲット（メンバーの3カード / 各グループ）の必要枚数と期待点を評価する
- 捨て札の選択
- 宣言するかどうかの判断（自分の手番 / 他家の捨て札への割り込みの両方）
- 難易度パラメータによる強さの調整

### 3. 自動対局ヘルパ（`src/engine/autoplay.ts`）

- 全員 CPU で1局を最後まで進め、統計を返す
- 各ステップで不変条件を検査できる

## 受け入れ条件

### 状態機械の基本

- [ ] `createGame(roster, rules, seed)` が配牌済みの初期状態を返し、同一シードなら完全に同じ状態になる
- [ ] `reduce` が入力の `state` を破壊しない（純粋関数である）
- [ ] `reduce` がタイマー・`Date`・`Math.random()` を一切使わない
- [ ] 各フェーズが受け付けないアクションを渡すと専用の例外が投げられる（黙って無視しない）
- [ ] `gameOver` に到達した後はどのアクションも状態を変えない

### フェーズ遷移

- [ ] `draw` で山札の先頭1枚が手番プレイヤーの手札に入り、`selfDeclare` へ遷移する
- [ ] `selfDeclare` で `SKIP_DECLARE` すると `discard` へ遷移する
- [ ] `discard` で捨てたカードが河に積まれ、`claimWindow` へ遷移する
- [ ] `claimWindow` で手番以外の全員が意思表示を終えると割り込み解決へ進む
- [ ] `TICK` で受付時間が尽きたとき、未表明のプレイヤーはパス扱いになる
- [ ] 誰も割り込まなければ次のプレイヤーの `draw` へ遷移し、`TurnChanged` が発行される
- [ ] 手番は反時計回り（プレイヤー ID の昇順）に進む

### 和了と補充

- [ ] 自分の手番での宣言（ツモ）で、他3人から等分が徴収される
- [ ] 他家の捨て札への割り込み（ロン）で、捨てたプレイヤーが全額を支払う
- [ ] **消費したカードのうち自分の手札から出た枚数と、補充される枚数が一致する**
- [ ] 宣言後、`gameOver` でない限り全プレイヤーの手札枚数が規定枚数に戻る（引いたカードをまだ持っているツモ中の手番プレイヤーだけ +1 枚）
- [ ] **ロンによる連続宣言の最中、既に捨て終わった手番プレイヤーの手札は規定枚数のままである**
- [ ] 補充で新たな役が成立した場合、続けて宣言できる（連続宣言）
- [ ] 連続宣言は `maxChainDeclare` 回で打ち切られ、無限ループしない
- [ ] **上限による打ち切りは例外ではなくフェーズ遷移で行われる**（役が成立していれば必ず宣言する CPU が例外で止まらない）
- [ ] **ロン後の連続宣言はツモとして精算される**（2回目以降は捨て札を消費していないため）
- [ ] ロン成立後、手番は捨てたプレイヤーの次へ進む（ロンしたプレイヤーの手番にはならない）
- [ ] **補充の途中で山札が尽きても精算は取り消されない**。取れるだけ補充して `gameOver(wallEmpty)` になる

### 割り込み優先度

- [ ] 複数のプレイヤーが割り込んだとき、点数が高い役を宣言したプレイヤーが優先される
- [ ] 点数が同じなら、捨てたプレイヤーから反時計回りに近いプレイヤーが優先される
- [ ] 優先されなかったプレイヤーは何も得ず、支払いも発生しない（頭ハネ）

### 不正入力に対する防御

- [ ] **`DECLARE` / `CLAIM` の候補は手札から再検証される**。実際には成立しない役や、点数を偽装した候補は例外で弾かれる
- [ ] 精算に使われるのは呼び出し側が渡した候補ではなく、エンジンが再計算した候補である
- [ ] `CLAIM` を手番プレイヤー自身が行うと例外になる
- [ ] `DECLARE` を宣言権のないプレイヤーが行うと例外になる
- [ ] 自分の手札にないカードの `DISCARD` は例外になる
- [ ] 既に意思表示済みのプレイヤーが再度 `CLAIM` / `PASS` すると例外になる

### 終了条件

- [ ] 山札が尽きたら `gameOver`（理由 `wallEmpty`）になる
- [ ] 誰かの点数が0以下になったら `gameOver`（理由 `bankrupt`）になる
- [ ] `GameOver` イベントに順位が含まれ、点数降順・同点はプレイヤー ID 昇順で決まる

### 不変条件（対局全体を通じて）

- [ ] **点数保存則**: 4人の点数の合計が常に `startingScore × playerCount` に等しい
- [ ] **山札単調減少**: 山札の枚数はどのアクションでも増えない
- [ ] **カード保存則**: 山札 + 全員の手札 + 全員の河 + 役として消費されたカードの合計が常に一定で、`uid` の重複がない
- [ ] `rngState` は対局中に変化しない（進行に乱数を使っていないことの証明）

### CPU AI

- [ ] **AI は他家の手札・山札の中身を参照できない**。入力は公開情報だけに限定された型で渡される
- [ ] AI は乱数を使わず、同じ入力に対して常に同じ判断を返す
- [ ] 役が成立していれば必ず宣言する（v1 の定石。「ダマポカジャン」は非搭載）
- [ ] 複数の役が成立しているとき、最も点数の高いものを宣言する
- [ ] どのターゲットにも寄与しないカードを優先して捨てる
- [ ] 難易度パラメータで挙動が変わり、既定値がプリセットとして提供される

### 自動対局

- [ ] シードを変えた自動対局を100局実行し、例外なく全局が `gameOver` に到達する
- [ ] 100局すべてで上記の不変条件（点数保存則・カード保存則・手札枚数）が各ステップで成立する
- [ ] 自動対局が統計値（終了理由の内訳・平均打牌数・宣言回数）を返す
- [ ] 統計値に回帰テストが設定され、AI やルールの変更で分布が壊れたら検知できる

## 成功指標

- `npm test` / `npm run lint` / `npm run typecheck` / `npm run build` がすべて PASS する
- Step 4（対局 UI）が `createGame` / `reduce` / `GameEvent` / AI 関数だけを前提に着手できる
- エンジン層が React・`src/config/` に依存していない（`npm run lint` の `no-restricted-imports` で担保）

## スコープ外

以下はこのフェーズでは実装しません:

- 対局 UI・アニメーション・宣言ボタン・タイマー表示（Step 4）
- 実時間の経過処理（エンジンは `TICK` を受け取るだけで、時計は Step 4 の UI 層が持つ）
- BET・精算・所持コイン永続化（Step 5）
- 「ダマポカジャン」（役を伏せて同色を狙う戦術）の AI 実装（v2 以降）
- 対局のセーブ / ロード・リプレイ再生（`rngState` は土台として保持するのみ）
