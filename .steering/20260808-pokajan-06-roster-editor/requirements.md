# Step 6: ロスターエディタ + ルール設定 — 要求内容

## 背景

Step 5 で BET → 対局 → 精算のループが閉じ、ゲームとしては完成した。
一方で **登場キャラクターは同梱の創作キャラ22人に固定**されており、
PRD が掲げた「組織やチームが自分たちの画像を設定して、そのチームならではの
ゲームを作れる」という中心的な価値がまだ実現していない。

本ステップでロスターを編集可能にし、プロダクトの目的を満たす。
同時に、これまで `TODO(要実機確認)` を付けてきたルール値
（`startingScore` / `group3.sameColor` / 順位倍率 / 持ち時間 / 初期コイン）を
画面から調整できるようにする。

## 要求

### R1: 画像の保存（IndexedDB）

**ユーザーストーリー**
利用者として、自分たちの写真でカードを作るために、
画像をアップロードして保存したい。

**受け入れ条件**

- [ ] 画像を `imageId → Blob` の形で IndexedDB に保存・取得・削除できる
- [ ] localStorage には画像を置かない（約5MB制限に収まらないため）
- [ ] IndexedDB が使えない環境でも**例外で落ちず**、画像なしで遊べる
- [ ] 保存済みの画像はリロード後も残る
- [ ] ライブラリを追加せずに実装する

**優先度**: P0

---

### R2: 画像のアップロードと縮小

**ユーザーストーリー**
利用者として、スマートフォンで撮った大きな写真をそのまま選んでも
動作が重くならないよう、自動で適切なサイズに変換してほしい。

**受け入れ条件**

- [ ] `<input type="file" accept="image/*">` から画像を選べる
- [ ] canvas で **256×256 の webp** に変換してから保存する
- [ ] 縦横比が異なる画像は**中央を正方形に切り出す**（引き伸ばさない）
- [ ] 画像でないファイル・壊れた画像を選んだ場合、エラーを表示して既存の状態を壊さない
- [ ] 変換の寸法計算が単体テストできる形になっている

**優先度**: P0

---

### R3: ロスターの編集

**ユーザーストーリー**
利用者として、自分たちのチーム構成を再現するために、
グループとメンバーを自由に追加・削除・並べ替えたい。

**受け入れ条件**

- [ ] グループの追加・削除・リネームができる
- [ ] メンバーの追加・削除・リネームができる
- [ ] メンバーをグループに割り当て・解除できる
- [ ] `validateRoster` の結果が**編集中にリアルタイムで**表示される
- [ ] 不正な構成（グループ数 < 4 / グループ人数が 3〜5 の外 / プール不足）では**保存できない**
- [ ] 警告（どのグループにも属さないメンバー）は保存を妨げない
- [ ] 保存した内容はリロード後も残り、対局に反映される
- [ ] 「デフォルトに戻す」で同梱ロスターへ復帰できる

**優先度**: P0

---

### R4: ロスターの書き出し・読み込み

**ユーザーストーリー**
利用者として、作ったロスターをチームで共有するために、
1ファイルで書き出して他の端末で読み込みたい。

**受け入れ条件**

- [ ] ロスター定義と画像を含む**単一の JSON ファイル**を書き出せる
- [ ] 書き出したファイルを読み込むと、画像込みで元の状態に戻る
- [ ] 壊れた JSON・別形式の JSON を読み込んでも**既存のデータを壊さない**
- [ ] 書き出し時にファイルサイズの目安を表示する
- [ ] 依存ライブラリを追加せずに実装する

**優先度**: P1

---

### R5: ルール設定

**ユーザーストーリー**
利用者として、遊びやすいバランスに調整するために、
点数や持ち時間などの数値を変更したい。

**受け入れ条件**

- [ ] 点数表（4役 × 通常/同色）を編集できる
- [ ] `startingScore` / `bonusPerCard` / 持ち時間3値 / 初期コイン / 順位倍率を編集できる
- [ ] `TODO(要実機確認)` の項目にその旨の注記が出る
- [ ] 「デフォルトに戻す」で既定値へ復帰できる
- [ ] 変更が対局に反映される
- [ ] 変更した値はリロード後も残る

**優先度**: P1

---

### R6: 不正な設定値でゲームが壊れない

**ユーザーストーリー**
利用者として、極端な値を入れてしまってもゲームが起動不能にならないでほしい。

**背景**: 保存されたルール上書きは localStorage から読まれ、**そのままエンジンに渡る**。
localStorage はユーザーが直接編集でき、別バージョンの本アプリが書いた値も残りうる。
`handSize: 0` や `deckSize` がプール枚数を超える値が入ると、配牌の時点で例外になり
**タイトル画面すら出せなくなる**。永続化されるため、リロードしても回復しない。

**受け入れ条件**

- [ ] 保存されたルール上書きは、エンジンに渡す前に検証される
- [ ] 検証に通らない値は既定値に倒し、**アプリは必ず起動する**
- [ ] 画面からも不正な値は入力・保存できない
- [ ] 保存されたロスターについても同様に、検証に通らなければ同梱ロスターに倒す

**優先度**: P0（R3・R5 と不可分）

---

### R7: カードへの画像表示

**ユーザーストーリー**
利用者として、設定した画像が対局中のカードに出てほしい。

**受け入れ条件**

- [ ] `imageId` があるメンバーのカードには画像が表示される
- [ ] 画像がないメンバーは従来どおり名前とアクセントカラーで描画される
- [ ] 画像の読み込みに失敗しても対局は継続する
- [ ] object URL が解放され、対局のたびに増え続けない

**優先度**: P0

---

## スコープ外

| 項目                         | 理由                                       |
| ---------------------------- | ------------------------------------------ |
| CPU 難易度の調整画面         | `AiConfig` は `RulesConfig` の外。v2 以降   |
| ロスターのクラウド共有       | サーバーを持たない方針                     |
| 画像のトリミング UI          | 中央切り出しの自動処理で代替               |
| 対局中の設定変更             | 対局は開始時の `rules` で最後まで進む      |

## 非機能要件

- **エンジンの純粋性を維持する**: 検証関数は `rules` / `roster` を引数で受け取る純粋関数
- **`src/storage/` は UI を参照しない**（`.oxlintrc.json` で機械的に禁止済み）
- **DOM に依存する処理を最小の層に閉じ込める**: テスト環境は `node` で jsdom を入れていないため、
  寸法計算・検証・CRUD などの判断は DOM に触れない純粋関数として切り出す
- 検証ゲート: `npm run lint && npm run typecheck && npm test && npm run build && npm run format:check`
- E2E: `tests/e2e/roster.spec.ts`（編集 → 保存 → 対局に反映 → リロード後も保持）
