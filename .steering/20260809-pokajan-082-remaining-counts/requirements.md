# Step 8-2: 残り枚数の確認 — 要求

## 背景

プレイテストで挙がった不満のうち、8-1 で扱わなかった最後の1つ。

> 残り枚数が読めない。同じ絵札が何枚生きているかを、手札と河から目で数えるしかない。

テンパイしても「その札はもう3枚とも場に出ている」ことに気づけず、
上がれない待ちを抱えたまま打ち続けることが起きる。

計画書は
[docs/ideas/pokajan-presentation-and-counts-plan.md](../../docs/ideas/pokajan-presentation-and-counts-plan.md)
の「2. 残り枚数の確認（Step 8-2）」。本ステアリングは**その範囲のみ**。

## 要求

### R1. 手札ホバーで各色の残枚数が分かる

手札の絵札にマウスを乗せると、そのメンバーの**色ごとの想定残枚数**が出る。

- **自分の手番でなくても出る。** 調べたいのは打つ瞬間だけではない
- 焦点（Tab キー）でも出る。ただし捨てられない局面のカードは `disabled` の
  `<button>` で焦点を取れないため、キーボードからは自分の手番のときだけになる

### R2. テンパイ時に待ち一覧が出る

あと1枚で役が完成する状態のとき、待ちの一覧を手札の上に常時表示する。

- 各行に「メンバー（色）・残枚数・成立する役・点数」を並べる
- **残0 の行は淡く落とす。** 役はできるが、その札はもう場に無い
- **並び順は「残っている待ちが先、その中で点数降順」。**
  件数が多いときは上位のみを出して残りは件数だけ示すが、そのとき
  点数だけで並べると**高い役の待ちが全部死んでいる局面で、生きている待ちが
  打ち切りの下に隠れる**。それでは「上がれそうか」を確かめるという目的を果たさない

### R3. 算出はエンジンの純粋関数に置く

- **他家の手札に到達する経路を型として持たせない。**
  `countUnseen` は `GameState` を受け取らず、公開情報だけの `VisibleCards` を受け取る
- 状態に触るのは `toVisibleCards` の1箇所だけ

### R4. 数え落としがないこと

見えているカード = **自分の手札 + 全員の河 + 全員の成立済みの役（`declared`）**。

成立済みの役を数え落とすと、消費されたカードが「まだ引ける」ことになる。
これは**残枚数を過大に見せる**ため、上がれない待ちを抱えさせるという
本機能が解こうとしている問題そのものを再生産する。

### R5. 確定値だと誤解させない

残枚数 = `rules.copiesPerMemberColor` − 見えている枚数 は**上限であって確定値ではない**。

`buildDeck` はプール（117〜144枚）から `deckSize`（100枚）しか抜かないため、
残枚数の内訳は次のようになる。

```
残枚数 = 山札に残っている枚数 + 他家の手札にある枚数 + そもそも山札に入らなかった枚数
```

画面のラベルは「残」とだけ書き、「山に残り N 枚」のような確定的な言い方はしない。

## 非機能要求

| 項目 | 要求 |
| ---- | ---- |
| レイヤ | `src/engine/unseen.ts` は React・`src/config/` に依存しない（既存のゲートで機械的に守られる） |
| 決定性 | `Math.random()` / `Date` を使わない。表示順も決定的にする |
| ルール値 | `copiesPerMemberColor` / `colors` は `RulesConfig` から受け取る。定数を直接書かない |
| 画面幅 | 375px でツールチップと待ち一覧が画面からはみ出さない |
| ファイルサイズ | 全ファイル 400 行以内（フェーズの区切りごとに `wc -l` で測る） |

## 範囲外（今回やらないこと）

- **河のカード・中央のボーナスタイルのホバー**（v2）
- **触れる端末での残り枚数の確認**（長押し。待ち一覧が代替する）
- **山札に残っている期待値の表示**（残枚数 × 山札 / 未確認の総数）
- **CPU AI が残枚数を使うこと。** AI の強さは今回の対象外で、
  `AiView` にフィールドを増やさない（7-5 で `payments` を外したときと同じ負債になる）
- 精算バランス調整（ユーザーが保留と明言）
