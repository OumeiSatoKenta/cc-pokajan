# Step 7-4: 和了の確認ゲート — 要求

## 背景

ポカジャンは**和了しても局が終わらない**（連続宣言があり、最大8回まで続く）。
そのため和了は「局の締めくくり」ではなく「局の途中で何度も起こる出来事」で、
現状は**画面上部に小さなトーストが出るだけ**で進行は止まらない。

結果として、

- 誰が何の役で何点取ったのかを**読む前に盤面が先へ進む**
- 点数がいつ動いたのか分からない（トーストは点数表示と離れた場所に出る）
- CPU 同士の和了は特に見落としやすい

Step 7-5 で作る演出（アバターのカットイン・得点移動・順位移動）は
**進行が止まっていることが前提**なので、その土台を先に作る。

## 今回やること

**和了が起きたら対局の自動進行を止め、確認ボタンを押すまで進まないようにする。**

- `LoopState` に和了の情報（`pendingWin`）を持たせる
- `useGameLoop` の**3つの効果すべて**を止める
- 最小限の `WinOverlay`（誰が・何の役で・何点 + 確認ボタン）を出す
- 役割が重複する `YakuToast` を廃止する

> **確認済みの決定**（Step 7 の計画時）: **すべての和了で止める**。CPU 同士の和了でも
> 確認を押すまで進まない。連続宣言は最大8回まで起こりうるため、最悪ケースでは
> 確認を8回押すことになる。ユーザーはこれを承知のうえで選択している。

## 受け入れ条件（全て達成）

- [x] 自分がツモると進行が止まり、確認を押すまで動かない
- [x] **CPU 同士の和了でも止まる**
- [x] **止まっている間に持ち時間が減らない**（止め忘れると演出中にツモ切りされる）
- [x] 連続宣言では回数分だけ確認を押す（1回の和了につき1回）
- [x] 確認を押すと進行が再開する
- [x] 和了で終局した場合、確認を押してから結果画面が出る
- [x] 演出には**適用前後の点数**が含まれる（7-5 の得点移動が使う）
- [x] **停止中はエンジンへのアクションが受理されない**（画面の無効化だけに頼らない）
- [x] 既存の E2E 63 件が通る
- [x] 全ファイルが 400 行を超えない（今回追加・変更したものはすべて基準内。
      `board.css` 406 / `yaku.ts` 410 / `deck.ts` 406 は 7-4 以前からの積み残し）

## 最大の落とし穴（着手前に確認済み）

**確認ゲートを入れると E2E の進行ヘルパが止まり、対局を進めるテストが全滅する。**

| ファイル | 箇所 | 症状 |
| -------- | ---- | ---- |
| `tests/e2e/table.spec.ts` | `playToEnd` / `playUntilClaimWindow` / `waitForMyDiscard` | 確認ボタンを知らないため、`pass-button` を押し続けて**受理されず**タイムアウト |
| `tests/e2e/casino.spec.ts` | `playToEnd` | 同上。BET → 精算のループが閉じなくなる |
| `tests/e2e/table.spec.ts` | 「役成立のトーストは一定時間で消える」 | `YakuToast` の廃止で対象そのものが消える |

`tests/e2e/rules.spec.ts` は対局を開くだけで進めないため**影響しない**（確認済み）。

**ヘルパの修正を同じステップで行う。** 後回しにすると、落ちているのが
仕様変更のせいなのか新しい欠陥なのか区別できなくなる。

## やらないこと（Step 7-4 の範囲外）

| 項目 | 送り先 |
| ---- | ------ |
| アバターのカットイン | Step 7-5 |
| 得点の移動アニメーション | Step 7-5（**データは今回そろえる**） |
| 順位の移動アニメーション | Step 7-5（`computeRanking` の抽出も 7-5） |
| 配色・質感の作り込み | 未計画 |

`WinOverlay` は今回**最小限**にする。見せ方を作り込んでから止め方を直すと、
演出を2回書き直すことになる。
