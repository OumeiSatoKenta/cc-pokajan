# Step 7-2: 4方向レイアウト — 要求

## 背景

Step 7-1 でカードの部品（`.card--small` / `CardBack` / `MemberTile`）がそろい、
河・伏せ札・ボーナスが「絵」で出るようになった。しかし**配置は縦一列のまま**で、

- 他家3人は画面上部に横並び（誰が左隣で誰が右隣か分からない）
- 河は自分の分しかない（他家が何を切ったかは直近1枚のチップだけ）

という状態にある。麻雀の卓では**位置そのものが情報**（上家＝自分が鳴ける相手、
下家＝自分の捨て牌が渡る相手）なので、位置が失われると盤面から読み取れることが減る。

## 今回やること

対局画面を **3×3 の卓レイアウト**に組み替える。

```
          [対面]
[上家]    [中央]    [下家]
          [自分]
```

- 中央 = 山札残り・ボーナス・登場グループ
- 各家（他家3人）は**自分の伏せ手札と自分の河**を持つ
- 左右の席（上家・下家）の伏せ札は**縦積み**にする
- 幅 30rem 以下では 1 列の縦積みに切り替える

## 受け入れ条件（全て達成）

- [x] 対面が上、上家が左、下家が右、自分が下に配置される
- [x] 席の位置は `humanSeat` からの**相対位置**で決まる（`playerId` 直指定にしない）
- [x] 4人全員の河がカードの絵で並ぶ（自分の河も含む）
- [x] 他家の伏せ札の枚数が `hand.length` と一致する
- [x] 伏せ札の出力に他家のメンバー名・画像・記号・色が含まれない（7-1 の性質を維持）
- [x] 900px で卓レイアウトが破綻しない
- [x] 375px で 1 列に縦積みされ、横スクロールが出ない
- [x] `PlayerSeat` の「直近の捨て札チップ」が河に置き換わり、`.chip` が残骸にならない
- [x] `TableScreen` / CSS が 400 行を超えない
- [x] 既存の E2E 54 件が通る（**壊れるものは意図を保ったまま追随させる**）

## やらないこと（Step 7-2 の範囲外）

| 項目 | 送り先 |
| ---- | ------ |
| プレイヤーアバター | Step 7-3 |
| 和了の確認ゲート（`pendingWin` / `CONFIRM_WIN`） | Step 7-4 |
| カットイン・得点移動・順位移動の演出 | Step 7-5 |
| 配色・カードの質感の作り込み | 7-2 完了後にスクリーンショットを見て判断 |

## 既知の影響（着手前に洗い出したもの）

| 影響 | 対応 |
| ---- | ---- |
| E2E `河が捨てた絵札で並ぶ` の `river-card` 総数 0 件アサーション | **4人分の河になると CPU の捨て札を巻き込んで落ちる。** 自分の河に限定する識別子を足す |
| `.chip` の CSS（`table.css:229-249`） | `PlayerSeat` から消えるので**まとめて削除**する（未使用 CSS を残さない） |
| `river__title` / `river__empty` | 4つ並ぶと文字が卓を埋める。位置で誰の河か分かるので**見出しは持たせない**（`aria-label` は残す） |
| `seat-score` の testid 3件 | 他家3人のまま維持する（既存アサーションを壊さない） |
| `card-backs` の testid 3件 | 同上 |
