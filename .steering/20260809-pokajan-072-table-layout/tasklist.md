### 学んだこと

1. **同じものを数えている検査は、対象が増えた瞬間に別のものを数え始める。**
   E2E の「河が捨てた絵札で並ぶ」は `getByTestId('river-card')` の**総数**を
   0 → 1 で見ていた。河が1人分しかなかったときはそれで正しかったが、
   4人分になると自分の番までに CPU が切った札が混ざる。
   落ちてくれるならまだよく、**先に CPU が捨てていれば「1枚になった」が
   偶然成立して通ってしまう**（初期値0のアサーションが先に落ちるので今回は防げたが、
   それは順序が味方しただけ）。着手前に洗い出して `my-river` に限定したので、
   「自分が1枚捨てたら自分の河に1枚出る」という**元の意図をそのまま保てた**。
   Step 7-1 の `testId` 分離と同じ形の問題が、今度は**同じ識別子のまま数が増える**
   という別の入り口から来た。

2. **キャストは型の嘘を後の変更まで持ち越す。**
   `seatOrientation` は `'self'` を返しうるが、人間を除外した後なので実際には来ない。
   `as OpponentOrientation` で黙らせれば1行で済むが、それは
   「今の実装ではそうなる」という**たまたま成り立っている条件**を型に焼き付ける行為で、
   将来 `seatOrientation` の分岐が変わっても何も教えてくれない。
   `orientation === 'self' ? 'top' : orientation` と明示的に畳んだ。
   CLAUDE.md の「不正な入力を黙って無視しない」は `switch` だけの話ではなかった。

3. **代用品は、本物が入った時点で消さないと二重表示になる。**
   `PlayerSeat` の「直近の捨て札チップ」は河が無かったころの代用品だった。
   河を入れたのに残せば、同じ情報が劣化した形で並ぶ。
   CSS（`.chip`）も同時に消した。**使われない CSS を残すと次に触る人が現役だと誤解する**。
   Step 6b で `.card__image` が丸ごと欠けていたのはこの逆向きの事故で、
   どちらも「CSS と使用箇所が対応していない」という同じ根を持つ。

4. **確認用の足場そのものにバグが入る。**
   画像付きの見え方を確かめるスクリーンショット用スペックで、
   IndexedDB に `{ id, blob }` を入れてしまった（`putImage` は Blob をそのまま入れる）。
   `getImage` は `instanceof Blob` で弾くので画像が出ず、**一度は
   「画像なしと同じに見える」を正常だと思いかけた**。
   検証の道具が黙って失敗すると、検証したつもりだけが残る。
   実装と同じ API（`putImage`）を通していれば起きなかった。

### 積み残し（意図的）

- **空の河が `min-height: 3.4rem` を占める。** 対局開始直後は席と自分の手札の上に
  空白が見える。1枚目が出た瞬間に卓がガタつくほうが害が大きいので確保を選んだが、
  見た目を詰める段で背景の描き分け（河の枠を薄く示す等）で解消したい
