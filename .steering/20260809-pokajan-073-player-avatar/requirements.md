# Step 7-3: プレイヤーアバター — 要求

## 背景

Step 7-2 で卓が4方向になり、各席が伏せ手札と河を持つようになった。
しかし**席にいるのは名前だけ**（「対面」「上家」）で、誰と打っているのかが分からない。

麻雀ゲームでは席にプレイヤーのアイコンがあり、和了演出（Step 7-5）でも
そのアイコンがカットインする。**演出を作る前にアバターを入れておかないと、
カットインを2回作ることになる**ため、演出より先にこの段を置いている。

## 今回やること

**4つの座席それぞれに画像を設定できる**ようにする。

- 保存は既存の IndexedDB（`src/storage/assets.ts`）をそのまま使う。新しいストアは作らない
- 座席 → 画像ID の対応を `prefs`（localStorage）に持つ
- タイトルから開く新画面「プレイヤー設定」で設定する
- 書き出し／読み込み（`rosterBundle`）にアバターを含める
- 対局画面の各席にアバターを出す

## 着手前に見つけた既知の欠陥（本ステップで必ず塞ぐ）

**`RosterEditor` の保存がアバター画像を全部消す。**

```ts
// src/ui/screens/RosterEditor.tsx:117
await pruneImages(usedImageIds(roster))
```

`pruneImages` は**渡された ID 以外を全て削除する**。`usedImageIds(roster)` は
ロスターが参照する画像しか返さないため、アバターを同じ IndexedDB に置いた瞬間、
**ロスター設定を保存するだけで全アバターが消える**。

同じ理由で以下も壊れる。

| 箇所 | 症状 |
| ---- | ---- |
| `RosterEditor.tsx:55` `nextId('img', usedImageIds(roster))` | アバターが使っている ID と衝突し、**別人の画像で上書きされる** |
| `RosterEditor.tsx:75` 書き出しの画像収集 | アバターの画像が書き出しファイルに入らず、読み込み側で欠ける |

**3箇所すべてが「画像を参照しうるものを全部数える」ことを必要としている。**
1箇所ずつ直すと、次に画像の持ち主が増えたときに同じ抜けが再発する。
